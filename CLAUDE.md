# Fleet Checklist – project rules

## Folder layout

| Folder             | What goes in it                                                                 |
| ------------------ | ------------------------------------------------------------------------------- |
| `screens/`         | Every Power Apps screen, old and new: one file per screen                       |
| `scripts/`         | Scripts that build or set up parts of the system (e.g. `build_forms.py`, `build_lists.py`) |
| `files/`           | Reference and source documents used to put the system together (PDFs, .docx, .xlsx) |
| `email-templates/` | HTML email templates for the flows                                              |

Root holds only `README.md`, `CLAUDE.md`, `PROJECT_HANDOVER.md` and `PROJECT_HISTORY.md`.

## Rules

- **New screens go straight into `screens/`.** Whenever a new screen is suggested or designed, create its file in `screens/` automatically, without being asked. Don't just describe it in chat.
  - Name it `scr<Name>.txt` (PascalCase, `scr` prefix, `.txt` extension), e.g. `screens/scrRunEnd.txt`.
  - The file holds the screen's full YAML/Power Fx (the screen definition you paste into Power Apps).
  - Control names use a type prefix and no spaces or `_1`/`DataCard1` suffixes: `scr` screen, `frm` form, `crd` form card (e.g. `crdOdometer`), `btn` button, `lbl` label, `txt` text input, `drp` dropdown, `gal` gallery, `cam` camera, `img` image, `ico` icon, `rec` rectangle, `con` container, `bcr` barcode reader, `chk` checkbox (outside a card's data value), `dte` date picker. Controls inside a form card keep Power Apps' default names (`DataCardValueN`, `DataCardKeyN`, `ErrorMessageN`, `StarVisibleN`); only the card itself is renamed (testing whether renaming them broke the drop-downs, Nov 2026). Names must be unique across the whole app. Never name a control after a Power Fx function (e.g. not `SubmitForm`, `Back`, `Navigate`).
  - Drop-down options come from SharePoint, never hard-coded lists like `["Yes", "No"]`, so option changes are made in SharePoint only.
  - In `Choices(...)` and `DataSourceInfo(...)`, refer to columns by their **internal** name (`Choices([@'Fleet Checklist'].'field_4')`), not the display name. With display names the pasted drop-downs open empty (confirmed Nov 2026).
  - Use the **Classic/DropDown** control for single-choice fields, never Classic/ComboBox: a ComboBox pasted in from screen code opens with an empty list even when its code is correct (confirmed Nov 2026). Dropdown cards use `AllowEmptySelection: =true` (so nothing is pre-selected), `Default: =ThisItem.field_N.Value` (the card's own internal field; `Parent.Default.Value` errors with "'Value' isn't recognized" after pasting), `Items.Value: =Value`, and the card's `Update: =<dropdown>.Selected`.
  - **Fleet Checklist items are an explicit Yes / No** (meeting with Pawan's team, 23 Nov 2026). Each item has two `Classic/CheckBox@2.1.0` boxes captioned "Yes" and "No", and nothing is ticked at the start.
    - The Yes box is the card's `DataCardValueN`; the No box is `chk<Card>No`.
    - Yes box: `Default: =ThisItem.<field>.Value = "Yes"`, `OnCheck: =Reset(chk<Card>No)`. No box: `Default: =ThisItem.<field>.Value = "No"`, `OnCheck: =Reset(DataCardValueN)`.
    - Card `Update: =If(<yes>.Value, {Value: "Yes"}, If(<no>.Value, {Value: "No"}, Blank()))`.
    - The comment is its own card, `crd<Card>Cmt`, on the item's `<field>Cmt` column. It shows and is required when the problem answer is ticked: No, or Yes for Accident damage.
  - **Driver Declaration statements stay single checkboxes** (19 Nov 2026 decision, unchanged): ticked saves "Yes", unticked saves "No", with the question text beside the box and the box laid over it so tapping the text ticks it. In a card: `Default: =ThisItem.field_N.Value = "Yes"`, card `Update: ={Value: If(<checkbox>.Value, "Yes", "No")}`, card `Required: =false`.
  - Don't give a checkbox `MetadataKey: FieldValue` inside a card; the card's `Update` reads it by name. `Classic/CheckBox` has **no `AccessibleLabel` property**: paste fails with error PA2108 (confirmed Nov 2026). Manager/office sign-off choices (e.g. Approval for Delivery, Send for Repairs) stay as drop-downs.
  - **`screens/scrPreTrip.txt` is generated.** Change items, order, wording, photo rules or truck-type rules in `scripts/checklist_items.json`, then run `py -3 -I scripts/build_pretrip_screen.py screens`. Never hand-edit the generated screen; changes to its chrome (header, footer, sign-off cards) go in the generator's templates. The screen shows each column's SharePoint display name, so a wording change is a display-name rename (`scripts/create_checklist_v2_columns.js`, `MODE = 'rename'`), not an app change.
  - **Photos** are taken with the in-app Camera control, never Add Picture or the gallery. A retake replaces the photo with the same Type and Item in `colPhotos`. Checklist photo types: Odometer, Accessory, Tyre, Profile, Accident, Defect.
  - Any property whose formula contains `: ` (a record like `{ctxEdit: Blank()}`, or text like `"Driver: …"`) must use the block form `Prop: |-` with the formula on the next line. Written on one line, paste fails with PA1001 "found invalid mapping" (confirmed Nov 2026).
  - Changes to an existing screen are made in its file in `screens/`; don't create a second copy.
- **Look and feel (GF brand, phone-first).** Every screen uses the same pattern: white header (`con<Screen>Header`: back icon, `'gf-logo'` image, title + subtitle), a 4-colour brand stripe under it (`con<Screen>Stripe`), a scrolling body on a light background, and a fixed white footer for the main action. Sizes come from `Parent.Width` / auto-layout containers, never fixed pixel widths. Touch targets are at least 48 px high.
  - Palette (from `gf-logo.png`): teal `RGBA(8, 144, 144, 1)` (primary buttons, section headings), dark teal `RGBA(0, 112, 112, 1)` (titles, pressed), teal tint `RGBA(226, 243, 242, 1)` (hover), cyan `RGBA(0, 184, 216, 1)`, yellow `RGBA(248, 208, 0, 1)`, lime `RGBA(160, 200, 80, 1)` (stripe only), ink `RGBA(31, 41, 51, 1)` (text), muted `RGBA(96, 108, 118, 1)`, line `RGBA(208, 216, 218, 1)`, background `RGBA(243, 246, 246, 1)`.
  - Primary button: teal fill, white text, radius 10, height 56. Secondary button: white fill, 2 px teal border, dark-teal text.
  - Text must fit a ~360 px phone: free-text inputs (comments, remarks, descriptions, names) use `Mode: =TextMode.MultiLine` (height 80–104); any label that can run past one line gets `AutoHeight: =true` + `Wrap: =true`, and a fixed-height card around it gets `Height: =<base> + (lbl.Height - <label's original height>)`. Gallery rows leave room for 2-line text.
  - The logo must be uploaded to the app's Media as `gf-logo` (from `gf-logo.png` in the project root).
- **Roles.** Access is controlled by the SharePoint list **GF Fleet Checklist App Users** (Title = name, `UserEmail` lower case, `AppRole` choice Admin/Reviewer/Driver, `ActiveYN`), created by `scripts/create_app_users.js`. `scrHome.OnVisible` sets `varRole` ("Driver", "Reviewer", "Admin", or "None" if not registered/inactive). Roles stack: Reviewer can do everything Driver can, Admin everything Reviewer can. Gate buttons with `Visible: =varRole in [...]`, and screens a role must not open by hiding the screen's root container (`Visible: =varRole in [...]`) and showing a full-screen label whose `OnSelect` navigates to scrHome. Never put `Navigate` in a screen's `OnVisible` (Studio error: "Navigate cannot be used here"). Hiding a button is not security: list permissions in SharePoint are the real boundary. Users are added, re-roled and removed only on `scrUsers` through the `SyncAppUser` flow, which writes the App Users row and sets membership of the SharePoint groups **Fleet App Drivers** (Driver) / **Fleet App Reviewers** (Reviewer, Admin). Never Patch App Users from the app directly, and don't put app users in the site's Members group.
- **Offline (run sheet).** The run sheet works without signal: the trip (`varRunSheet`, a plain record with `LocalKey`, `ID`, `Synced`, `PendingSubmit` and the trip/return fields) and stops (`colRunStops`, each with `LocalKey`, `ID`, `Synced`) are saved on the phone with `SaveData` ("fcRunHeader", "fcRunStops") and sent by `btnRunSync` **only after Submit** (`PendingSubmit`): the trip is created once with all its fields and Status "Open", then each stop without an `ID` is created. **Drivers can only add rows, never edit them** (SharePoint permission level Fleet App Driver has no Edit), so driver-side code must never Patch an existing Run Sheets / Run Sheet Details / Fleet Checklist / Driver Declarations row, only `Defaults(...)`; a stop that already has an `ID` can't be changed in the app. Never write to Run Sheets / Run Sheet Details directly from another button; save locally and `Select(btnRunSync)`. `varRole` is cached in "fcRole". Invoice photos are queued in `colInvoicePhotos` (`RunKey`, `StopKey`, `Slot`, `Img`, `Uploaded`), saved as "fcRunPhotos" and loaded with the other two. Unlike the trip and stops, `btnRunSync` uploads them **on every sync** (through `SaveFleetPhoto` with RunKey/StopKey), then blanks the image and marks the row Uploaded. The run only clears when no photo is waiting, and it then calls the `RunSheetSubmitted` flow. Photos are taken with the in-app Camera control only, never Add Picture or the gallery (user's decision). Time fields are two 2-digit boxes (`txt<X>HH` / `txt<X>MM`) joined into "HH:MM" by a hidden `lbl<X>Val` label. Offline only works in the Power Apps mobile app. Checklist and declaration still need signal.
- **New scripts go in `scripts/`.** The build scripts take the output folder as their first argument. Point it at `files/`, e.g. `python scripts/build_lists.py files`.
- **Generated or reference documents go in `files/`.**
- Never create new files in the project root.
